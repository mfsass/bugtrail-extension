# BugHunter 1.0.0 Release Notes

## Purpose

BugHunter 1.0.0 is the first Chrome Web Store release. It captures a QA reproduction
trail in the browser side panel and produces a developer-ready Markdown bug report.

Previous builds were distributed as an unpacked pilot package under the name
**BugTrail**. This release renames the product to **BugHunter** and moves distribution
to the Chrome Web Store.

## Renamed from BugTrail

The rename is complete across the manifest, UI, storage keys, runtime messages, docs,
and brand assets.

**What this means for existing pilot installs:** BugHunter stores its state under a new
local storage key, so it will not see a trail recorded by an older BugTrail build. Any
unfinished BugTrail trail should be copied or saved before upgrading. Testers should
remove the old unpacked BugTrail extension so they are not running two recorders at
once.

**Application annotations are backward compatible.** Apps already marked up with
`data-bugtrail-component`, `data-bugtrail-action`, or `data-bugtrail-field` continue to
work. BugHunter reads `data-bughunter-*` first and falls back to the `data-bugtrail-*`
form, so annotated applications do not need to change. New annotations should use
`data-bughunter-*`.

## Included Capabilities

- Chrome MV3 side-panel extension.
- Built-in access for the configured rewards admin production, stage, dev, localhost, and `127.0.0.1` environments.
- One-click `Add this site` flow for other internal QA apps, gated on Chrome's own permission prompt.
- Click, route, input, select, submit, and bug-marker capture.
- API summary capture through `webRequest`, with richer fetch/XHR evidence from the page bridge.
- Console error, warning, uncaught error, and unhandled rejection capture.
- App and environment inference from known URLs, localhost, and common environment hostnames.
- Markdown report preview, copy, and `Save .md`.
- Clipboard screenshot of the visible app tab.
- Redaction for common sensitive values in payloads, URLs, console output, field values, and report text.
- Bounded local evidence retention.
- Stale recording auto-stop after 8 hours.
- Shareable zip packaging with checksum metadata.

## Also in this release

- Fixed environment inference for staging hostnames. The previous pattern had an
  alternation precedence bug that could classify an unrelated host ending in `staging`
  as a Stage environment.
- Removed an unused exported alias and an unreachable runtime message type.
- Extracted the browser automation used by the runtime smoke test into
  `scripts/lib/chrome-harness.mjs`, now shared with the store asset generator.
- Verbose Chrome logging during the runtime smoke test is now opt-in via
  `BUGHUNTER_VERBOSE_BROWSER_LOG`, so the release gate output stays readable.
- Added `npm run capture:store`, which drives the real extension through a recording and
  generates the Chrome Web Store screenshots and promo tiles from live UI.

## Known Boundaries

- BugHunter is local-first and stores trail state in `chrome.storage.local`.
- `webRequest` cannot read response bodies; response summaries depend on the page-level fetch/XHR bridge.
- Screenshots are pixel images and are not redacted.
- Chrome Web Store review of the optional all-URLs host permissions may require the
  rationale in `docs/permissions-and-privacy.md`.

## Rollback

For Web Store installs, unpublish the item or roll back to the previously published
version in the Developer Dashboard. Published version numbers can never be reused.

For unpacked installs:

1. Open `chrome://extensions` or `brave://extensions`.
2. Remove BugHunter or reload the previous extracted `chrome-mv3` folder.
3. Re-run the previous package through the same install steps.

For managed rollout, remove or replace the extension entry in the Chrome Enterprise policy.
