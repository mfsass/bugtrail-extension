# BugTrail Production Readiness

## Current Signoff Gates

- Unit tests must pass with `npm test`.
- TypeScript must pass with `npm run compile`.
- Production extension build must pass with `npm run build`.
- Documentation integrity must pass with `npm run validate:docs`.
- Production dependency audit must pass with `npm run audit:prod`.
- Shareable package must be created with `npm run zip`.
- Browser runtime smoke must pass with `npm run smoke:runtime` after `npm run build`.
- Complete release verification must pass with `npm run verify:release` before sharing the pilot zip.
- Release metadata must be generated and validated with the zip: `.sha256` sidecar and `release-manifest.json`.

## Pilot Acceptance Checklist

Use `docs/live-pilot-checklist.md` to record pass/fail evidence during the authenticated Spur admin pilot.

- Load `.output/chrome-mv3` as an unpacked extension in Chrome or Brave.
- Confirm built-in Spur rewards admin sites can start a trail without an extra prompt.
- Confirm app/environment fields are inferred correctly and can still be overridden.
- Open another internal app and confirm `Add this site` grants access once and then enables `Start Trail`.
- Confirm user-added sites appear under `Trusted sites` and can be removed.
- Confirm denied permissions and unavailable browser actions show visible side-panel errors.
- Record a flow with a click, input, route change, successful API call, failed API call, and console error.
- Confirm the report preview shows deduped API calls and clear step correlation.
- Confirm completed reports can be copied and saved as Markdown.
- Confirm a failed API step remains visible even after many low-value filter/input interactions.
- Confirm copied report redacts email, phone, token, password, session, cookie, and card-like data.
- Confirm unsupported pages such as `chrome://extensions` cannot start recording.

## Runtime Smoke

On Windows, Brave can be selected explicitly:

```powershell
$env:BUGTRAIL_BROWSER='C:\Program Files\BraveSoftware\Brave-Browser\Application\brave.exe'
npm run smoke:runtime
```

The smoke test uses a temporary browser profile and local fixture page. It verifies the built extension can start a trail, capture click/input steps, capture a failed API call, capture a console error through the page bridge, redact sensitive console data, stop the trail, and read the stored session.

## Known Production Boundaries

- BugTrail is local-first and stores trace state in `chrome.storage.local`.
- Extension-level request-body capture is scoped to the active recording tab and stops when the trail is stopped or cleared.
- Stored trail evidence is bounded to prevent runaway local storage during long QA sessions.
- Active recordings older than 8 hours are auto-stopped on restore so stale browser sessions do not keep collecting.
- Response summaries depend on the page-level fetch/XHR bridge; extension-level `webRequest` cannot read response bodies.
- Dynamic site access is user-managed through Chrome optional host permissions.
- Wider rollout should move from unpacked install to private Chrome Web Store or Chrome Enterprise policy.
- QA install and update steps are documented in `docs/qa-install-guide.md`.
- Live pilot evidence should be captured with `docs/live-pilot-checklist.md`.
- Permission and privacy rationale is documented in `docs/permissions-and-privacy.md`.
- Release artifact integrity metadata is generated by `npm run release:metadata` and checked by `npm run validate:release-metadata`.
- Documentation integrity is checked by `npm run validate:docs`.
- Pilot release notes are documented in `docs/release-notes-0.1.0.md`.
